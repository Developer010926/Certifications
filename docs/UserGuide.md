# Руководство пользователя

## 1. Назначение системы

Certifications используется для ведения сотрудников, их действующих контрактов и сертификаций, необходимых для продления контрактов.

В системе есть два типа доступа:

- обычный сотрудник просматривает только собственные данные;
- администратор управляет сотрудниками, контрактами и сертификациями, а также может открыть собственную страницу.

## 2. Вход

1. Откройте приложение.
2. Введите **Табельный номер**.
3. Введите **Пароль**.
4. Нажмите **Войти**.

Табельный номер проверяется без учёта регистра и пробельных символов. Пользователь без активного контракта войти не может.

При ошибке приложение показывает общее сообщение и не раскрывает, существует ли введённый табельный номер.

## 3. Выбор режима администратора

После входа администратор выбирает:

- **Моя страница** — просмотр собственных данных;
- **Администрирование приложения** — работа с сотрудниками и сертификациями.

Последний выбранный режим сохраняется и предлагается при следующем входе. Позже режим можно изменить через кнопку **Сменить режим**.

Обычный сотрудник сразу переходит на страницу **Моя страница**.

## 4. Моя страница

На личной странице отображаются:

- табельный номер и ФИО;
- должность, подразделение и отдел;
- дата начала контракта;
- введённая или рассчитанная дата окончания;
- текущий статус;
- история сертификаций.

Страница доступна только для чтения. Пользователь не может самостоятельно менять персональные данные или контракт.

Кнопка показа пароля открывает пароль в отдельном диалоге. После закрытия диалога пароль удаляется из памяти страницы.

## 5. Обзор сертификаций

В административном режиме раздел **Обзор сертификаций** показывает по одной строке для сотрудника и его последнего активного контракта.

Доступны фильтры:

- ФИО или табельный номер;
- подразделение;
- статус;
- диапазон расчётной даты окончания;
- отображение неактивных сотрудников.

Таблицу можно сортировать и переключать по страницам. Для строки доступны переходы к сотруднику, контракту и последней сертификации.

### Значения статуса

| Статус | Значение |
| --- | --- |
| **Контракт действителен** | До warning-периода ещё достаточно времени |
| **Ожидается сертификация** | Наступил warning-период, сертификацию следует запланировать |
| **Сертификация в процессе** | Существует незавершённая сертификация |
| **Сертификация отсутствует** | Наступил alert-период, но незавершённая сертификация не создана |
| **Не применяется** | У сотрудника нет активного контракта |

Статус и расчётную дату окончания определяет сервер. Интерфейс только отображает полученные значения.

## 6. Сотрудники

Раздел **Сотрудники** позволяет:

- найти сотрудника по ФИО или табельному номеру;
- включить в список сотрудников без активного контракта;
- открыть карточку сотрудника;
- создать нового сотрудника.

Физическое удаление сотрудника отсутствует. Для прекращения работы закрывается его активный контракт.

## 7. Создание сотрудника

Нажмите **Создать сотрудника** и заполните одну форму, содержащую данные сотрудника и первого контракта.

Обязательные поля сотрудника:

- табельный номер;
- имя;
- фамилия.

Отчество необязательно. При необходимости включите признак администратора.

Обязательные поля первого контракта:

- должность;
- дата контракта.

Подразделение, отдел и явная дата окончания необязательны. Параметры warning, alert и периода продления первоначально заполнены значениями по умолчанию.

Сотрудник и первый контракт создаются одной операцией. Если контракт создать невозможно, сотрудник также не создаётся.

После успешного сохранения система показывает сгенерированный пароль. Скопируйте и передайте его пользователю безопасным способом. Пароль не показывается автоматически повторно после закрытия диалога, но администратор может отдельно запросить его раскрытие.

## 8. Карточка сотрудника

Администратор может изменить:

- табельный номер;
- имя;
- отчество;
- фамилию;
- признак администратора.

Изменение табельного номера сразу изменяет login пользователя. Новый номер должен оставаться уникальным.

В карточке также доступны:

- текущий контракт;
- история сертификаций;
- переход к управлению контрактом;
- показ текущего пароля;
- генерация нового пароля.

После генерации нового пароля прежний пароль сразу перестаёт работать.

## 9. Контракт

У сотрудника может быть только один активный контракт.

В разделе управления контрактом администратор может:

- просмотреть данные действующего контракта;
- закрыть контракт;
- создать новый контракт после закрытия предыдущего;
- просмотреть историю сертификаций;
- создать новую сертификацию.

Если `Valid To` не заполнено, расчётная дата окончания определяется как дата контракта плюс установленное количество лет продления.

Закрытие контракта требует даты и подтверждения. После закрытия сотрудник теряет возможность входа, пока ему не будет создан новый активный контракт.

Если данные контракта были изменены другим пользователем, система может показать конфликт. В этом случае обновите данные с сервера и повторите действие после проверки.

## 10. Сертификация

Для создания сертификации обязательны:

- экзаменатор;
- дата сертификации.

Нельзя создать новую сертификацию, пока предыдущая сертификация этого контракта не завершена.

Этапы работы:

1. Создание записи с экзаменатором и датой сертификации.
2. Ввод **Даты протокола** после прохождения сертификации.
3. Ввод **Даты отправки документов**.
4. Нажатие **Завершить сертификацию** и ввод даты возврата документов.

Даты должны идти в хронологическом порядке. Нельзя заполнить следующий этап без предыдущего.

После возврата документов:

- сертификация считается завершённой;
- контракт получает новую дату `Valid To`, рассчитанную от даты протокола;
- статус снова становится **Контракт действителен**;
- завершённую сертификацию нельзя вернуть в работу или изменить.

Исправление дат задним числом допускается только до завершения сертификации.

## 11. Работа с паролями

- Пароль генерирует система.
- Администратор может показать или сгенерировать пароль сотрудника.
- Пользователь может показать только собственный пароль.
- Новый пароль немедленно заменяет старый.
- Пароль должен содержать минимум восемь символов, буквы и цифры.
- Специальные символы разрешены, но не обязательны.
- Не сохраняйте пароль в заметках, URL или browser storage.
- Закрывайте диалог после безопасной передачи пароля.

## 12. Даты

Интерфейс отображает календарные даты в русском формате:

```text
ДД.ММ.ГГГГ
```

Используйте календарь или вводите дату в этом формате. Система работает с календарными датами без времени суток.

## 13. Ошибки и конфликты

- **Нет связи с сервером** — проверьте подключение и повторите запрос.
- **Нет прав** — действие недоступно текущей роли.
- **Конфликт** — данные уже изменились или операция противоречит текущему состоянию; обновите страницу.
- **Ошибка поля** — исправьте значение рядом с отмеченным полем.
- **Сессия завершена** — выполните вход повторно.

Если ошибка повторяется, запишите выполняемое действие и время возникновения, затем передайте информацию администратору системы.

## 14. Выход

Нажмите **Выйти** в верхней панели. Сессия завершается на сервере, после чего приложение возвращается на страницу входа.
